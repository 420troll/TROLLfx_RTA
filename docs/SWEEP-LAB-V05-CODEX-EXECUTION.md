# TROLLfx Sweep Lab V0.5 — Codex execution handoff

**Base:** `feature/v05-sweep-lab-prework` forked from the **working** `feature/force-native-rta-v04-auto-service`. Treat this as a new feature, not a rewrite of the live analyzer.

## 0. Non-negotiable separation

**LIVE RTA:** keep V0.4 16/31 LED display, VST identity `TfRA`, existing parameter order, sound-level measurements and auto daemon unchanged. Keep regular capture and updates live during normal RTA use.

**SWEEP LAB:** a separate explicit measurement workflow. Playback/capture occurs only after user presses START; offline processing and static or saved graph only **after capture completes**. Do not use the live RTA's power-averaged band values to calculate a room transfer function.

The V0.4 service already supervises one bundled ARMv7 analyzer, uses UMIK `hw:U18dB,0` and port 8096, and is owned by the VST shared worker. Review `docs/FORCE-NATIVE-V04.md`, `plugins/TrollfxRta/src/TrollfxRta.cpp`, `src/trollfx_rta.c` before changes.

## 1. Specific first implementation target

Ship a **portable offline DSP kernel and executable test harness first**. Only after passing tests integrate audio capture and VST pages.

Sweep defaults for proposal (editable in UI): log 20–20,000 Hz, 10 seconds, peak **-30 dBFS**, 48 kHz; verify upper cutoff is below usable Nyquist. Begin with an output mute/low-level audible warning and brief 10 ms fade. No sweep on project load or state restore. An explicit CANCEL must silence generated output promptly. Do not change MPC routing.

For sample time `t` in [0,T], `L=T/ln(f1/f0)`, phase `phi(t)=2*pi*f0*L*(exp(t/L)-1)`, samples `A*sin(phi(t))`. Ramp edges; frequency derivative is `f0*exp(t/L)`. Keep exact generator parameters and audio buffer timestamps in session metadata. Compare algorithm's generation to pyfar before assuming compatibility: pyfar may use a different sweep type/phase/fade convention.

Capture the **actual UMIK recording** plus preserved original sweep, not the live spectrum summary; keep PCM32 float or native captured PCM with conversion metadata. Record pre-roll, post-roll and a leading recognizable alignment marker. The marker must be chosen and checked for speaker/room playback artifacts; never assume same-device sample clock.

## 2. Independent clocks and deconvolution

The Force output clock and UMIK USB clock are independent. Use at least start/end timing evidence or repeated markers to estimate *both* fixed lag and clock ratio. A single initial cross-correlation is insufficient to validate drift over a 10–20s measurement. Resample or fit the actual captured sweep timing to the played reference, and report residual error; if drift is unobservable, label phase/group delay **unreliable** and offer magnitude-only results with warnings.

Use regularized spectral inverse, `H(f)=Y(f)*conj(X(f))/(|X(f)|^2+lambda(f))`, with calibrated/guarded in-band bins, consistent FFT normalization, and explicit anti-wrap padding. Alternatively implement a properly normalized Farina inverse filter and validate it against the same known impulses. Avoid a naive `Y/X` division near zeros. Document regularization, band limitation, noise floor, and gating. Align recovered IR to leading direct arrival without erasing late reflections; preserve absolute time origin separately.

Validate from synthetic two-tap fixture generated by:

```sh
python3 scripts/make-sweep-fixture.py --output build/sweep-fixture
python3 -m unittest discover -s tests -p 'test_sweep_fixture.py'
```

The fixture intentionally contains a **0.5-gain direct tap**, **0.125-gain reflection**, 35 ms reflection separation, and an extra leading capture delay. Its files are **synthetic**: no microphone, distortion, sample-rate drift, or SPL. The expected samples are in `expected.json`. Extend fixtures for gain mismatch, 100 ppm clock drift, clipping, silence, nonlinear saturation and finite noisy rooms.

**First numerical acceptance:** recovered IR has correctly aligned direct and reflection peaks, relative echo/direct amplitude within ±1 dB, separation within 1 sample on no-drift synthetic test, in-band magnitude ±1 dB on pure-gain reference at adequate SNR. Add robust parameterized tests, not just generated fixture existence. Verify finite outputs, bounded time/memory and invalid input rejection. Use reproducible offline pyfar results as an independent oracle. Tests must run in GitHub Actions without Force hardware.

## 3. Explicit mic handoff

Never let V0.4 continuous ALSA reader and Sweep Lab capture open `hw:U18dB,0` concurrently. Preferred architecture: extend same measurement daemon with an **exclusive capture state machine** and buffered sweep session API while normal live-FFT updates pause. When Sweep Lab returns to IDLE, restore regular capture automatically, including after errors/cancel. No separate mic-opening process by default.

Recommend service transitions `LIVE -> ARMING -> RECORDING -> PROCESSING -> READY -> LIVE`. Control pages may show READY results after live RTA resumes. If the Force host isn't active, service must still behave deterministically. Use session IDs and reject a second START while running; ensure a lost VST instance does not leave a session pinned forever.

Avoid starting/stopping/restarting the whole V0.4 daemon for every sweep if stateful handoff is reliable. Do not change UMIK gain or Force Internal Audio. SPL remains provisional unless an actual verified reference exists.

## 4. Playback and handshake

The VST creates test audio inside its normal audio output callback using a **precomputed, immutable sweep buffer** and only RT-safe index advancement/mixing. Never write WAV, allocate, call socket/ALSA, block, lock or deconvolve in audio callback. Define whether sweep replaces or mixes with passthrough; default should prevent unwanted program content contaminating test measurement. User selects intended output channel(s). Playback should be audible only on explicit START; provide an enforced level cap and visible confirmation before unsafe increases.

Sequence: arm mic, acquire timestamp/pre-roll, acknowledge ARMED, send start-ready notification to audio-thread state using lock-free primitives, output marker and sweep, record through tail, stop, save immutable session artifacts, then analyze on worker. Track xrun/dropout counters and any clip flags; mark invalid rather than plotting plausible false results.

## 5. Graph design: feasibility gate

The MPC Plugin Builder skin uses parameter-bound `FilmStrip` graphics and static images. **It is not yet proven to redraw arbitrary saved line graphs at runtime.** Before promising a native Force high-res graph, test whether parameter-bound graphic controls can display a decimated static graph or dynamic image in this SDK and real Force firmware. Fallback: save HTML/PNG/SVG graphs in a persistent Sweep Lab session folder for use in a local browser, while offering a coarse 16/31-band saved-result overview inside the plugin. The browser fallback must not interfere with the live RTA or require Internet.

User wants **offline** sweep response, with zoom, smoothing, cursor and A/B eventually. One high-quality static result with correct axes is better than an animated but inaccurate plot.

## 6. Files, metadata, and reproducibility

Session directory contains reference sweep WAV, raw capture WAV, computed impulse-response WAV, frequency response CSV (Hz, linear gain/dB, unwrapped phase where valid), measurement.json, and graph PNG/SVG. Include actual sample rates, input orientation 0/90, calibration file hash, gain/reference provenance, playback channel, requested/actual sweep duration, start/end alignment, drift estimate, clipping, background noise, gate window, smoothing, inverse method and version. Require export be repeatable offline on WSL/PC without Force.

Only label absolute SPL 'calibrated' if independently anchored. Mic 7033298 frequency correction is **not** a proof of absolute SPL.

## 7. Open-source sources and licensing

- [pyfar sweep generation](https://pyfar.readthedocs.io/en/latest/modules/pyfar.signals.html) and [deconvolution](https://pyfar.readthedocs.io/en/latest/modules/pyfar.dsp.html): use MIT library in **host-side validation**, compare exact windowing and deconvolution normalization before porting.
- [Chirplab](https://github.com/loudifier/chirplab): MIT and helpful for capture/measurement architecture; do not bundle heavy Python/Qt in Force.
- [Open Sound Meter](https://opensoundmeter.com/): GPL; architectural inspiration only unless a deliberate license compatibility decision is made.
- [Farina ESS explanation](https://audio.js.org/modules/measure-ir/): inverse sweep, harmonic separation and normalization require tests.
- Preserve existing PFFFT notices and third-party attributions; explicitly audit each borrowed code path's license before copying.
