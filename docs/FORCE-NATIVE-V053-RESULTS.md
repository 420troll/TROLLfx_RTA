# TROLLfx RTA V0.5.3 — Full-Screen Saved Sweep Results

## Pages and bindings

V0.5.3 replaces the single crowded V0.5.2 results page with **SWEEP LED RESULTS** and **SWEEP GRAPH** sub-tabs under the existing Sweep Results function key. This keeps the skin within the Force's six function-key slots while providing two separate full-size views. Both occupy the MPC SDK's documented 1280 × 628 tab content area (physical screen coordinates begin 110 px below the top). Dynamic content ends at x=1008, leaving the documented right-side Q-Link overlay area (approximately x ≥ 1025) clear.

The LED page gives the 31 saved response bands a 402 px tall viewport and retains their band labels, smoothing selector, saved-measurement selector, result status, and diagnostic. Both LED level and peak marker data come from the selected saved measurement. Live RTA peak parameters are not bound to these pages.

The graph page shows 31 logarithmically positioned 1/3-octave response samples from 20 Hz to 20 kHz. The fill is a vertical parameter-bound `Slider` `ColourBar` and its bright red sample trace is a parameter-bound 25-frame image overlay. These are documented MPC components; unlike `Plotter`, `Slider` is marked well-trodden in the pinned SDK. The bars and markers update only after a capture completes or the selected measurement/smoothing mode changes. The display is static between those events. The selected smoothing defaults to 1/6 octave. Raw and smoothed full-resolution CSV/SVG outputs remain generated by the DSP engine; the native graph displays the selected smoothed response only.

This is a bounded-resolution native response graph, not a dynamically drawn arbitrary polyline. The SDK documents no custom VST editor drawing callback, dynamic image upload, or SVG widget. V0.5.2's 62 Plotter widgets accepted by its validator produced no visible curve on Force hardware, so V0.5.3 removes Plotter entirely. The filled log-spaced sample columns and bright sample-top trace use supported parameter-bound components and preserve the graph's response shape at the available 31 measurement centers.

## Measurement export repair

The raw response CSV continues to be written with `max_digits10`. When reading older V0.5.2 files, if the frequency axis is non-increasing, the reader attempts a narrowly verified repair: it reads the original `impulse.wav` sample count/rate and `measurement.json` sweep limits, then accepts reconstruction only if every old CSV frequency string exactly matches the legacy six-significant-digit serialization for the corresponding FFT bin. Magnitude, gain, phase, and row count are preserved. If the checks fail, processing returns a specific error.

Reprocessing a recovered session writes only `frequency-response-smoothed.csv` and `frequency-response.svg`; it leaves `frequency-response.csv`, `capture.wav`, `reference.wav`, `impulse.wav`, and `measurement.json` byte-for-byte unchanged. The diagnostic parameter (index 249) reports legacy-axis recovery and common processing failures. Parameters 0–217 and their meanings are preserved; graph markers append at 218–248 and the diagnostic at 249.

## API and visual verification limits

The pinned MPC Plugin Builder SDK is used at `febd2ca5bd9eb16c4a412837196e145566bc981b`. Its UI reference describes tab size, Q-Link overlap, image film strips, and colour-bar sliders. Its Plotter is explicitly “less tested”; the previous real-Force no-render result is the reason this version uses colour bars and film-strip markers instead.

The generated PNGs in `docs/images/v053-*.png` are **Pillow layout simulations**, composed from the generated skin artwork and illustrative response values. They are not screenshots from MPC firmware and do not prove that firmware 5.0.18 renders the components correctly. The package is an evaluation build; actual Force page rendering and readability still require a controlled touchscreen test. No deployment or MPC restart is part of this build.
